# Долголетие / TravelDataBase

Локальная картотека людей и мероприятий для Windows и macOS. Основной пользователь работает с карточками, участниками, фотографиями и документами; локальный `admin` управляет учётной записью и настройками защиты. Внешний сервер для обмена между ноутбуками не требуется.

Доступны два варианта запуска: настольное приложение Electron и веб-версия, включая Docker. Они используют общий интерфейс и функции базы.

Приложение использует Next.js 15, React 19, HeroUI 3, Prisma 6, SQLite3 Multiple Ciphers и Electron. Поиск FTS5, записи и история синхронизации находятся в одной SQLite-базе.

## Первый запуск

В настольной версии откройте приложение, один раз задайте пароль `admin`, войдите как `admin` и создайте единственного основного пользователя. Затем нажмите «Вход пользователя» и войдите под созданной учётной записью. Пароли — от 12 символов. Admin не может просматривать карточки или скачивать документы.

Данные настольной версии сохраняются в отдельной папке TravelDataBase профиля ОС и переживают обновление приложения. Сессия не переживает перезапуск. Не переносите папку установленного приложения вместо файла обмена.

Для разработки нужен Node.js 22.14 или новее; поддерживается актуальный Node.js с Node-API 10. На новой установке:

```sh
cp .env.example .env
npm ci
npm run prisma:generate
npm run build
npm start
```

В `.env` задайте случайный `SESSION_SECRET` длиной не менее 32 символов. Адрес — `http://127.0.0.1:3000`. Для разработки: `npm run dev`. В браузерном режиме сохранение запускает скачивание; гарантированный системный диалог выбора пути предоставляет настольная версия.

Docker: `docker compose build && docker compose up -d`. Порт опубликован только на loopback. Контейнер хранит данные в подключённых `data` и `uploads`; `.env` подключается только для чтения. Миграции выполняет приложение через свой драйвер после открытия базы. Prisma CLI и `db push` при запуске не используются.

## Обновление прежней установки

Перед обновлением остановите приложение и сохраните прежние каталоги базы и вложений. Сохраните фактическое значение прежнего `DATABASE_URL`: относительные пути Prisma разрешаются относительно каталога `prisma`. Для переноса старой установки временно укажите её старый `APP_PASSWORD`; мастер запросит его как подтверждение владения. После создания admin прежний пароль больше не используется для входа. На новой установке `APP_PASSWORD` оставляют пустым.

Не запускайте Prisma Studio, `migrate deploy` или `db push` на зашифрованной базе. Версионные SQL-миграции выполняются приложением после разблокировки с сохранением FTS5 и его триггеров.

## Пакетная загрузка

В «Люди» или «База данных» откройте «Пакетная загрузка DOCX / XLSX»:

1. Выберите несколько локальных файлов и разберите их.
2. Проверьте заголовки таблиц и соответствие колонок полям карточки; неизвестные колонки сопоставьте вручную.
3. Просмотрите новых людей и дополнения. При неоднозначном совпадении выберите карточку либо создание нового человека. Для разных заполненных значений выберите итоговое значение; автоматической замены нет.
4. Исправьте ошибки или исключите проблемные строки. Подтвердите сохранение готового плана.

Телефон и паспорт остаются единственными полями карточки. Импорт не создаёт участия в мероприятиях. Пустая исходная ячейка не очищает ранее заполненное поле. Изменение карточек во время просмотра требует пересчёта и нового подтверждения. Повтор уже отправленного подтверждения возвращает результат без повторного создания людей.

Пределы: 12 файлов, 10 МБ на файл, 30 МБ на пакет, суммарно 10 000 строк и 60 таблиц. Поддерживаются DOCX-таблицы тела документа, XLSX-листы, многострочные заголовки, сохранённые результаты формул и даты Excel 1900/1904. Не поддерживаются OCR, DOC/XLS, парольные офисные файлы и таблицы колонтитулов. Неоднозначные даты, инициалы и ненадёжные числовые значения требуют проверки. Подробности — [контракт импорта](lib/batch-import/README.md).

## PDF и XLSX

В списке людей отмечайте карточки, включая разные страницы и результаты поиска. Перед экспортом выберите поля, их порядок, PDF/XLSX и портретную или альбомную ориентацию. Для XLSX ориентация применяется при печати. Последние успешно использованные параметры сохраняются для каждого вида отчёта.

Из общих сведений мероприятия экспортируются компактные сведения и таблица всех участников. Из вкладки участников — название, дата и таблица всех участников, включая участников с архивной карточкой. Одна строка соответствует одному человеку. Фото, документы и сведения об оплате не включаются в таблицы карточек людей.

Отчёт ограничен 10 000 людьми; чрезмерно длинный текст поля XLSX предлагается исключить или вывести в PDF. Номера телефонов и паспортов записываются текстом, с ведущими нулями; содержимое ячеек не превращается в формулы.

## Ручная синхронизация

В «База данных → Синхронизация через файл» нажмите «Сохранить файл обмена» и выберите путь на флешке. Передайте файл `.tdbsync` одному или нескольким ноутбукам. На получателе выберите файл и нажмите «Проверить и показать изменения». Если файл защищён, введите пароль, действовавший при его создании.

Проверьте изменения, возможные совпадения людей, конфликты и удаления. Принять удаление, оставить локальную запись или отложить её можно только явно. Независимые изменения разных полей объединяются. Часы ноутбуков не определяют победителя. Отложенные изменения остаются неподтверждёнными. После применения сохраните новый файл обмена для остальных ноутбуков.

Файл включает записи, оригиналы фотографий/документов и историю, необходимую для объединения. Локальный admin и его пароль не передаются. Пароль основного пользователя и защищённые параметры восстановления переносятся после выбора пользователя; прежние сессии отзываются. Более старый файл не откатывает новую ветку доступа. При разных ключах может потребоваться текущий пароль локальной базы.

Смену режима шифрования завершает admin: основной пользователь подтверждает записи, затем через предложенную кнопку выходит и входит как admin для подтверждения паролем или доступным ключом восстановления. Незавершённый перенос не объявляется успешной полной синхронизацией. После прерывания снова выберите исходный файл; журнал и сохранённые результаты предотвращают повтор записи. Файлы обмена ограничены 512 МБ. Подробности — [протокол синхронизации](lib/sync/README.md).

## Шифрование и восстановление

Шифрование включается и отключается в admin, в том числе для заполненной базы. Перед включением введите текущий пароль пользователя, сохраните показанный код восстановления отдельно от базы и подтвердите его сохранение. Отключение требует текущего пароля или кода восстановления. Основной пользователь управлять режимом не может.

Отключение шифрования сохраняет пароль учётной записи. Если пароль утрачен, сначала восстановите его по коду в разделе «Пароль и восстановление», сохраните новый код и затем отключите шифрование.

SQLite шифруется SQLite3 Multiple Ciphers, оригиналы и миниатюры — AES-256-GCM. Случайный ключ данных защищается контейнерами, открываемыми парольной фразой через Argon2id или кодом восстановления. На диске нет открытого ключа данных или открытого пароля. Admin знает только проверочные записи учётных записей и настройки; для операций защиты дополнительно нужен секрет основного пользователя.

Обычная смена пароля обновляет защиту ключа данных и отзывает сессии. Восстановление создаёт новый пароль и новый код восстановления. Оно не изменяет старые офлайн-копии: для старого файла может понадобиться прежний пароль. Без пароля и кода зашифрованное содержимое открыть нельзя. Включение защиты не шифрует ранее сохранённые внешние копии.

Преобразование создаёт и проверяет новое поколение базы и вложений, затем атомарно переключает метаданные доступа. Маркеры восстановления содержат только защищённые ключи и хеши. Незавершённая подготовка откатывается; зафиксированное переключение завершается после перезапуска, включая удаление исходных файлов. Обоснование формата — [решение по хранению](docs/STORAGE_DESIGN.md).

## Резервные копии

«База данных → Резервная копия» сохраняет ZIP при выключенном шифровании или защищённый `.tdbbackup` при включённом. Восстановление запрашивает пароль защищённой копии и поддерживает пробный запуск. Параметры доступа из резервной копии не заменяют текущую учётную запись.

Восстановление ZIP/TDBBACKUP добавляет и заменяет совпавшие записи либо заменяет всю базу по выбранному режиму. Оно не выполняет разбор конфликтов, предусмотренный синхронизацией. Для объединения работы ноутбуков используйте `.tdbsync`. Удалённые оригиналы могут сохраняться в локальной истории для ещё не синхронизированных ноутбуков; очистка карточек не является физическим стиранием этой истории.

Для полной аварийной копии остановленного приложения сохраните всю папку данных профиля, включая настройки доступа и поколения, а также исходный каталог вложений, если шифрование ещё не включалось. Храните пароль/код восстановления отдельно.

## Разработка и поставка

- `npm test` — серверные, форматные, UI-handler и файловые проверки на искусственных данных.
- `npm run typecheck`, `npm run lint`, `npm run build` — типы, статический анализ и production-сборка.
- `node e2e/run.cjs` — браузерная проверка в отдельной временной установке, без рабочей базы.
- `npm run desktop:pack` — сборка локального приложения; `npm run desktop:dist` — установщик.
- [Настольная оболочка и ограничения проверки](desktop/README.md).
- [Согласованный план](docs/DEVELOPMENT_PLAN.md), [статус реализации и приёмки](docs/IMPLEMENTATION_STATUS.md).

Подпись/нотаризация дистрибутивов и фактическая приёмка Windows/macOS на целевых устройствах описываются отдельно от успешной локальной сборки. Тестовые проверки не являются внешним аудитом криптографической реализации.

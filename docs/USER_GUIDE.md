# Инструкция пользователя TravelDataBase

## 1. Быстрый запуск на текущем Mac

Проект уже находится в папке `/Users/gurutom/Develop/TravelDataBase`.

1. Откройте приложение «Терминал».
2. Вставьте команды и нажмите Enter:

```bash
cd /Users/gurutom/Develop/TravelDataBase
npm start
```

3. Откройте в браузере http://127.0.0.1:3000.
4. Оставьте терминал открытым на время работы.

Чтобы остановить приложение, нажмите Control+C в терминале. Для следующего запуска повторите команды. Если приложение сообщает, что production build отсутствует, выполните `npm run build`, дождитесь завершения и снова выполните `npm start`.

Этот способ рассчитан на уже подготовленную копию проекта с установленными зависимостями. Для установки на другой компьютер используйте один из способов ниже.

## 2. Варианты установки

Можно пользоваться отдельным приложением или веб-версией через Docker. Это разные установки: данные между ними сами не переносятся. Для обмена используйте синхронизацию.

### Отдельное приложение на Windows

1. Получите у разработчика установщик для Windows. Исходная папка проекта не является установщиком.
2. Запустите установщик и следуйте его указаниям.
3. Откройте TravelDataBase через меню «Пуск» или созданный ярлык.
4. Выполните первоначальную настройку из раздела 4.

Docker и Node.js для готового приложения не требуются. Для последующих запусков достаточно ярлыка.

**Состояние поставки:** наличие готового Windows-установщика и его запуск на Windows нужно подтвердить у разработчика. Проверка совместимости исходного кода не заменяет проверку установщика на Windows.

### Отдельное приложение на macOS

Получите сборку под ваш Mac: Apple Silicon или Intel. Установите полученное приложение согласно инструкции к сборке, затем откройте TravelDataBase. Не используйте сборку для другой архитектуры.

Если macOS блокирует запуск неподписанной сборки, передайте разработчику текст сообщения. Не отключайте системную защиту целиком.

## 3. Веб-версия через Docker: Windows и macOS

### Что понадобится

- Docker Desktop для вашей операционной системы.
- Полная папка проекта, содержащая `docker-compose.yml`, `Dockerfile` и исходные файлы.
- Файл настроек `.env` в корне проекта.
- Интернет для первоначальной загрузки компонентов и сборки.

На Windows Docker должен работать с Linux-контейнерами. Если Docker Desktop требует установки или обновления WSL, выполните указания его установщика. При необходимости обратитесь к специалисту, обслуживающему компьютер.

### Подготовка настроек для новой установки

Если `.env` уже существует, **не заменяйте его**: там могут находиться настройки действующей базы.

Для новой установки скопируйте `.env.example` в `.env`. В строке `SESSION_SECRET` вместо примера задайте собственную случайную строку не короче 32 символов. Сохраните остальные параметры шаблона. Имя файла должно быть именно `.env`, без окончания `.txt`.

Для переноса старой установки сохраните её существующий `.env` вместе с данными. Не меняйте старые параметры доступа наугад.

### Первый запуск

1. Запустите Docker Desktop и дождитесь готовности.
2. Откройте терминал в папке проекта. На Windows можно открыть папку в Проводнике, в адресной строке набрать `powershell` и нажать Enter.
3. Выполните:

```bash
docker compose up -d --build
```

4. Дождитесь успешного завершения команды. Первоначальная сборка может занять несколько минут.
5. Откройте http://127.0.0.1:3000 в браузере.

Адрес работает на том компьютере, где запущен Docker. На каждом ноутбуке устанавливается собственная копия приложения.

### Повторный запуск

Запустите Docker Desktop, затем в папке проекта выполните:

```bash
docker compose up -d
```

Откройте http://127.0.0.1:3000. Терминал после этой команды можно закрыть.

### Остановка

В папке проекта выполните:

```bash
docker compose stop
```

Закрытие вкладки браузера само по себе приложение не останавливает. Данные сохраняются в папках проекта `data` и `uploads`; не удаляйте их.

### Если сайт не открывается

Проверьте, что Docker Desktop запущен. Затем выполните:

```bash
docker compose ps
```

Для получения сообщений об ошибках:

```bash
docker compose logs --tail=100 app
```

Передайте разработчику текст ошибки. Не публикуйте содержимое `.env`, пароли и персональные данные. Не удаляйте базу для устранения ошибки запуска.

## 4. Первый вход и учётные записи

1. При первом запуске задайте пароль суперпользователя `admin`. Используйте не менее 12 символов и сохраните пароль.
2. В административной панели создайте основного пользователя: задайте имя и пароль, повторите пароль.
3. Перейдите ко входу пользователя и войдите под созданной основной учётной записью.

`admin` управляет пользователем, доступом и настройками. Для работы с карточками людей и мероприятиями требуется основная учётная запись.

На каждом ноутбуке первоначальная настройка выполняется отдельно. Пароль локального `admin` не переносится обычной синхронизацией.

Если приложение обнаружило старую установку и требует подтверждения прежнего доступа, используйте её прежний пароль. Если он неизвестен, обратитесь к разработчику, сохранив исходные файлы базы.

## 5. Обычная работа

### Люди

Откройте раздел «Люди». Найдите человека через поиск или добавьте новую карточку. Заполните известные сведения и сохраните изменения. Для каждого человека предусмотрены один телефон и один номер паспорта.

Проверяйте паспортные номера и телефоны по оригиналу. Люди с одинаковыми ФИО могут быть разными людьми.

В карточку можно загружать фотографии и документы в форматах JPEG, PNG, WebP и PDF. Максимальный размер одного файла — 10 МБ. DOCX и XLSX используются для пакетной загрузки таблиц, а не как сканы карточки.

В открытой карточке человека или мероприятия кнопка «В архив» перемещает запись в архив после подтверждения. В разделе «Архив» выберите вкладку «Люди» или «Мероприятия», отметьте одну или несколько записей и нажмите «Восстановить выбранные» либо «Удалить выбранные навсегда». Обе операции требуют подтверждения. После окончательного удаления восстановление через архив недоступно; история обмена сохраняется для синхронизации с другими ноутбуками.

Удаление отдельного вложения не следует считать обратимым через архив: для восстановления может потребоваться резервная копия.

### Мероприятия

Создайте мероприятие, заполните общие сведения и добавьте людей через вкладку участников. Нажмите «Добавить участников», найдите людей и отметьте нужные карточки флажками. Выбор сохраняется при изменении поиска и переходе между страницами. Проверьте выбранных и нажмите «Добавить выбранных». Указанные в этом окне статус оплаты и суммы применятся к каждому выбранному человеку. Уже добавленные участники повторно не добавляются.

После пакетной загрузки люди не распределяются по мероприятиям автоматически: добавьте их вручную.

## 6. Пакетная загрузка из DOCX и XLSX

1. Сначала сохраните полную резервную копию.
2. Откройте «База данных» → «Пакетная загрузка DOCX / XLSX».
3. Выберите исходные файлы с таблицами. Можно выбрать несколько файлов.
4. Нажмите «Разобрать файлы».
5. Проверьте распознанные таблицы и соответствие колонок полям карточки. Исправьте соответствия, если заголовки нестандартные. Ненужные колонки исключите.
6. Нажмите «Показать план изменений».
7. Проверьте новых людей, дополнения и конфликты. При неоднозначном совпадении выберите нужную существующую карточку либо создание новой.
8. Если уже заполненные сведения различаются, явно выберите, какие оставить. Не объединяйте однофамильцев только по имени.
9. Исключите ошибочные строки. После изменения решений обновите итоговый план, если приложение это запрашивает.
10. Отметьте подтверждение проверки и нажмите «Подтвердить импорт».

До подтверждения записи в базу не вносятся. Пустые значения в исходной таблице не должны использоваться для стирания уже заполненных сведений.

Поддерживаются `.docx` и `.xlsx`. Старые `.doc` и `.xls` предварительно сохраните в новых форматах. Фотографии таблиц и сканы не являются таблицами DOCX/XLSX; распознавание текста из изображений этим импортом не выполняется.

За один раз можно выбрать до 12 файлов, каждый до 10 МБ, суммарно до 30 МБ. Большие наборы разделите на части. Если сеанс предварительного просмотра истёк или приложение перезапустилось, разберите исходные файлы повторно.

Телефоны и паспорта в Excel лучше хранить как текст: если Excel уже удалил начальные нули или округлил число, импорт не сможет восстановить исходные цифры.

## 7. Резервное копирование

Резервная копия нужна для восстановления после ошибки, поломки или потери компьютера. Синхронизация и экспорт в PDF/XLSX её не заменяют.

### Копия через интерфейс

1. Откройте «База данных» → «Резервная копия».
2. Выберите «Полный».
3. Нажмите «Сохранить копию».
4. Сохраните файл в отдельную папку, желательно на другом носителе. Добавьте дату к имени.
5. Убедитесь, что файл действительно появился и загрузка завершена.

Полная копия содержит деловые записи и текущие вложения. При включённом шифровании создаётся защищённый файл `.tdbbackup`, без шифрования — ZIP.

Сохраняйте копию в конце рабочего дня и перед массовым импортом, синхронизацией, изменением шифрования и обновлением программы. Храните несколько датированных версий.

Старые защищённые копии открываются паролем, действовавшим при их создании. Смена текущего пароля не изменяет ранее сохранённые файлы. Восстановление через интерфейс запрашивает пароль копии; не рассчитывайте заменить его кодом восстановления.

### Полная копия установки

Копия из интерфейса не заменяет сохранение всех локальных настроек доступа и истории синхронизации. Для полного восстановления конкретной установки дополнительно сохраняйте её папки при остановленной программе.

**Отдельное приложение:** полностью закройте TravelDataBase и скопируйте всю папку:

- Windows: `%APPDATA%\TravelDataBase`. Нажмите Win+R, вставьте путь и нажмите Enter.
- macOS: `~/Library/Application Support/TravelDataBase`. В Finder используйте «Переход» → «Переход к папке».

**Docker:** выполните `docker compose stop`, затем скопируйте из папки проекта целиком `data`, `uploads` и файл `.env`. После копирования выполните `docker compose up -d`.

Не ограничивайтесь одним файлом `data.db`: фотографии, настройки и зашифрованные данные могут находиться в других файлах. Не копируйте работающую базу обычным файловым копированием.

## 8. Восстановление

### Из копии, созданной через интерфейс

1. Сохраните резервную копию текущего состояния, если оно доступно.
2. Откройте «База данных» → «Восстановление из резервной копии».
3. Выберите ZIP или `.tdbbackup`. Для защищённой копии введите пароль времени её создания.
4. Выберите режим:
   - «Объединить» — импортировать сведения в текущую базу; совпавшие записи могут быть обновлены.
   - «Заменить» — заменить текущие деловые данные содержимым копии.
5. Сначала оставьте включённым «Пробный запуск» и нажмите «Показать план».
6. Проверьте результат. Для фактического восстановления отключите пробный запуск, повторно введите пароль защищённой копии и нажмите «Запустить импорт».
7. Подтвердите операцию и дождитесь завершения.

**Режим «Заменить» удаляет текущие деловые данные. Для полного восстановления выбирайте полную резервную копию, а не копию только людей или мероприятий.**

Восстановление копии отличается от синхронизации: режим объединения не предназначен для ручного разрешения каждого конфликта и может обновлять заполненные значения.

Настройки текущей учётной записи и режима шифрования сохраняются. Импорт защищённой копии в незашифрованную установку сам по себе не включает шифрование этой установки.

### Из полной копии папок

На той же установке остановите программу. Сохраните отдельно её нынешние папки, затем восстановите целиком папки из выбранной полной копии. Не смешивайте файлы разных дат. Для Docker восстановите вместе `data`, `uploads` и `.env`.

После запуска используйте доступ, действовавший на дату копии. Для создания параллельно работающего второго ноутбука используйте новую установку и синхронизацию, а не клонирование всей рабочей папки.

Периодически проверяйте восстановление на отдельной тестовой установке, не на единственной рабочей базе.

## 9. Синхронизация ноутбуков через флешку

Синхронизация запускается вручную и переносит записи, документы и фотографии. Можно использовать более двух компьютеров.

Максимальный размер файла синхронизации или резервной копии — **1 ГиБ (1 073 741 824 байта)**. Этот предел относится к архиву целиком; ограничение отдельного фото или документа остаётся 10 МБ.

1. На первом ноутбуке откройте «База данных» → «Синхронизация через файл».
2. Нажмите «Сохранить файл обмена», выберите флешку или другую папку и дождитесь сохранения `.tdbsync`.
3. На втором ноутбуке откройте тот же раздел и нажмите «Выбрать файл обмена».
4. Выберите именно `.tdbsync`, а не внутренний файл базы. Если файл защищён, введите пароль, действовавший при его выгрузке.
5. Нажмите «Проверить и показать изменения».
6. Проверьте предложенные дополнения, конфликты, совпадения людей и удаления. Удаление на другом ноутбуке требует вашего решения.
7. Для каждого спорного изменения выберите, что принять, сохранить локально или отложить.
8. Нажмите «Подтвердить выбранные решения» и дождитесь завершения.
9. На втором ноутбуке сохраните новый файл обмена с объединёнными данными и импортируйте его на первом.

Последний шаг необходим, если изменения были на обоих ноутбуках. Для третьего и следующих компьютеров повторяйте обмен объединёнными данными. Отложенные изменения остаются нерешёнными и могут появиться снова.

На время проверки плана желательно прекратить редактирование. Если база изменилась после построения плана, обновите его и проверьте повторно.

Перенос основного пароля и ключа восстановления требует принятия соответствующего изменения доступа. Пароль локального `admin` остаётся своим. Если требуется смена режима шифрования, завершите её под `admin` по указаниям приложения; может понадобиться текущий локальный пароль или код восстановления и пароль входящего файла.

Не заменяйте файлы работающей базы вручную и не используйте правило «более свежая дата файла всегда правильнее».

## 10. Шифрование, пароль и восстановление доступа

Шифрование необязательно для пакетной загрузки. Оно включается администратором и защищает базу вместе с фотографиями и документами.

### Включение

1. Сделайте резервную копию.
2. Войдите как `admin`, откройте «Шифрование базы».
3. Введите текущий пароль основного пользователя и подготовьте включение.
4. Сохраните выданный код восстановления отдельно от базы: например, на бумаге в защищённом месте.
5. Подтвердите сохранение кода и включите шифрование.
6. Дождитесь завершения; не выключайте компьютер. Для преобразования требуется свободное место на диске.

Код восстановления не является паролем `admin`. Если потеряны и пароль пользователя, и код восстановления, доступ к зашифрованным данным восстановить не получится.

### Смена пароля

В административном разделе «Пароль и восстановление» подтвердите доступ текущим паролем основного пользователя либо кодом восстановления, задайте новый пароль и повторите его. Если выдан новый код восстановления, сохраните его.

Передайте изменение доступа другим ноутбукам через синхронизацию. Старые резервные копии и ранее выгруженные файлы обмена автоматически не меняются: сохраняйте необходимые старые пароли отдельно и безопасно.

### Отключение

Отключение выполняется под `admin` с подтверждением текущим паролем пользователя или кодом восстановления. Если пароль забыт, сначала восстановите доступ и задайте новый пароль, затем отключайте шифрование. Отключение шифрования не отменяет вход по паролю.

## 11. Экспорт PDF и XLSX

Экспорт предназначен для просмотра, передачи таблицы и печати. Документы и фотографии в него не входят. Отчёты PDF/XLSX не становятся зашифрованными автоматически из-за включённого шифрования базы.

### Из раздела людей

1. Отметьте нужных людей флажками. Выбор страницы отмечает только текущую страницу; проверяйте итоговое количество.
2. Нажмите кнопку экспорта.
3. Выберите PDF или XLSX, поля карточки и порядок колонок.
4. Выберите книжную или альбомную ориентацию и сохраните файл.

Связанные мероприятия и другие связанные сведения в такой экспорт не добавляются. Последний выбранный набор полей запоминается. В XLSX ориентация задаёт параметры печати.

### Из мероприятия

- Экспорт общих сведений: компактная информация о мероприятии и таблица всех его участников.
- Экспорт из вкладки участников: название и дата мероприятия, затем таблица всех участников.

Перед экспортом выберите поля. По умолчанию каждому человеку соответствует одна строка, заголовки таблицы соответствуют выбранным полям.

## 12. Какое окно выбора файла что означает

- Пакетная загрузка: выберите исходные `.docx` или `.xlsx` с таблицами.
- Получение синхронизации: выберите полученный `.tdbsync`.
- Восстановление: выберите ранее сохранённую резервную копию ZIP или `.tdbbackup`.
- Сохранение копии, отчёта или обмена: выберите папку назначения и подтвердите имя файла.

В браузере файл может сразу попадать в «Загрузки», без отдельного окна. Если нажали «Отмена», файл не выбран или сохранение отменено: повторите нужное действие. Выбирать исполняемый файл программы или внутренний `data.db` для этих операций не нужно.

## 13. Частые проблемы

**Автоматический выход при бездействии.** По умолчанию через 15 минут без действий сессия завершается и база блокируется. Для продолжения войдите снова. В админке можно изменить интервал от 1 до 1440 минут либо отключить таймер. Фоновое обновление страницы само по себе не продлевает сессию. После обновления программы может потребоваться повторный вход.

**«Ожидается multipart/form-data» или ошибка синхронизации для большого файла.** В старой версии сервер мог обрезать загрузку после 10 МБ. Обновите программу и пересоберите контейнер, если используете Docker. В актуальной версии файл проверяется на полноту получения. Отключать шифрование для обхода этой ошибки не требуется.

**«Адрес уже занят» при запуске.** Возможно, программа уже работает. Сначала откройте http://127.0.0.1:3000. Не запускайте одновременно Docker и веб-приложение на одном порту.

**Нет данных после запуска другим способом.** У приложения и Docker разные хранилища. Вернитесь к прежнему способу запуска или перенесите данные через синхронизацию.

**Файл не открывается.** Проверьте, что выбрали подходящий тип файла и правильный пароль времени его создания. Сохраните оригинал, не меняйте его расширение вручную.

**Забыли пароль пользователя.** При включённом шифровании используйте код восстановления через административную панель. Для проблемы с паролем `admin` обратитесь к разработчику; код восстановления базы не сбрасывает пароль администратора.

**Перед обновлением.** Сделайте полную резервную копию, остановите программу и сохраните полную копию её папок. Не удаляйте данные и `.env` при замене версии.

**Для обращения за помощью.** Укажите Windows/macOS, способ запуска, выполнявшееся действие и текст ошибки. Не отправляйте всю базу с персональными данными без отдельного согласования.

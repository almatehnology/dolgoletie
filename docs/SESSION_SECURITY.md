# Завершение сессии при бездействии

По умолчанию вход основного пользователя и admin завершается через **15 минут бездействия**. Это ограничивает время доступа к оставленному открытым локальному приложению, сохраняя достаточно времени для обычной работы с карточками. В «Управление доступом → Завершение сессии при бездействии» admin может выбрать целое число от 1 до 1440 минут или отключить автоматическое завершение.

Настройка сохраняется только на этом устройстве в `security-settings.json` внутри каталога данных. Она переживает перезапуск и не входит в общую учётную запись, строгие схемы синхронизации или файл обмена. Отсутствующий файл означает 15 минут; повреждённый файл не отключает защиту молча и требует исправления настроек на устройстве.

Каждый вход заменяет предыдущую серверную сессию для обеих ролей. После выхода, истечения времени, нового входа или перезапуска сервера прежний cookie не предоставляет доступ, даже если позже хранилище снова открыто. Старые cookie без серверного идентификатора требуют повторного входа.

Только действия с мышью, клавиатурой, прокруткой или касанием в видимом окне сообщают об активности, не чаще одного раза в 10 секунд. Опрос состояния, фокус окна, загрузка страниц и фоновые запросы не продлевают сессию. Настройка таймера изменяет срок относительно последней активности, а не начинает новый отсчёт. Длительная операция без действий пользователя также может завершиться истечением сессии.

Серверный таймер отзывает сессию и закрывает зашифрованное хранилище без новых HTTP-запросов. Закрытие ждёт завершения текущей сериализованной операции с хранилищем; проверки доступа отклоняют истёкшую сессию сразу. Это рассчитано на один локальный серверный процесс, владеющий единственной базой и её ключом. Клиент очищает кеш данных и возвращает экран входа при завершении сессии. При обычном выходе и переключении роли сохраняется выбранный экран входа.

Проверки: `tests/auth-idle-session.test.ts`, `tests/auth-idle-routes.test.ts` и `tests/auth-activity-monitor.test.ts` используют управляемые часы вместо ожидания реальных минут. Проверка серверного таймера открывает настоящую зашифрованную SQLite-базу и подтверждает закрытие базы и недоступность ключа без HTTP-запроса в момент истечения.

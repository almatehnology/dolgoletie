# Изолированная браузерная acceptance QA

Из корня репозитория:

```sh
node e2e/run.cjs
```

Нужны уже установленные зависимости проекта и `@playwright/test`. Если Chromium отсутствует, запуск установит его стандартной командой Playwright. Сценарий не запускает build, не меняет package/lock и не использует production `.env`, `data` или `uploads`.

Каждый запуск создаёт новую временную папку `tdb-acceptance-*` и выводит её как `QA_ARTIFACTS`. Внутри находятся:

- `screenshots/`: снимки UI, включая экран при ошибке;
- `downloads/`: скачанные PDF/XLSX;
- `fixtures/`: вымышленные DOCX/XLSX/PNG; XLSX создан ExcelJS;
- `html-report/`, `results.json`, `test-results/*/trace.zip`: отчёт и воспроизводимые браузерные трассы;
- `server.log`, `evidence.json`: серверный журнал, статусы браузерных API-запросов и пути артефактов;
- `auth.json`, `data/`, `uploads/`: только тестовые данные.

Next dev привязан к `127.0.0.1:3327`; браузер использует `http://localhost:3327`, поскольку текущий Next нормализует loopback URL в middleware. Сервер работает из временной папки со ссылками на текущие `app`, `components`, `lib` и прочие явно перечисленные исходники. В `app` используются обычные каталоги и ссылки на отдельные файлы: Next не обнаруживает маршруты внутри ссылки на весь каталог. Копии `tsconfig.json` и `next-env.d.ts` защищают рабочие файлы от автоматических изменений Next. Production env-файлы в эту папку не попадают. Сервер получает абсолютный temporary `DATABASE_URL=file:...`, `DATA_DIR`, `AUTH_FILE`, `UPLOADS_DIR`, явно пустой `APP_PASSWORD=''`, случайный `SESSION_SECRET` из 48 байтов и отдельный `TDB_DIST_DIR=.next-qa-<suffix>`. Чужой сервер на этом порту не переиспользуется. Playwright останавливает QA-сервер при завершении, в том числе при провале теста; артефакты остаются для осмотра.

Пять последовательных проверок покрывают первый setup/admin/primary и API 403; пакетный DOCX/XLSX импорт с маппингом, ручным кандидатом, конфликтом, отсутствием записей до подтверждения и повторным apply; выбор людей между страницами и поиском, скачивание PDF/XLSX, сведения мероприятия и участников; вложение до/после шифрования и повторного входа; очистку состояния при переходах между ролями. XLSX отчёты повторно читаются ExcelJS и проверяются по участникам, числу строк и ориентации. Для PDF проверяется успешное скачивание и структура файла; печатная визуальная приёмка PDF остаётся отдельной проверкой.

Незавершённые advanced credential sync/admin pending не входят в утверждение о готовности. Сценарий не исправляет приложение: обнаруженные проблемы остаются родительскому исполнителю. Для открытия отчёта используйте `npx playwright show-report /absolute/tmp/path/html-report`, для трассы — `npx playwright show-trace /absolute/tmp/path/test-results/.../trace.zip`.
